# 计划 14：对话与立绘编号体系重构（face.tbl / 每句头像 / 角色覆盖）

来源：用户反馈 2026-09-11。这是"药引"级重构：编号体系立起来之后，
对话编辑器、表情编辑器、面板组织都跟着它走。

## face.tbl 编号体系

每个角色目录（`teams/<队>/chara/<ID>/`）新增 `face.tbl`：

```ini
[face]
#000 = 1.png      ; 头像，图片在本角色 face/ 文件夹
#001 = 2.png
#004 = smile.png  ; 自定义扩展位

[chara]
#000 = normal.png ; 立绘，图片在本角色 chara/ 文件夹
#001 = attack.png
```

- `#000 ~ #003` 为**保留语义位**，对应旧版配置：000 普通、001 攻击、
  002 日常、003 受击——旧代码按语义取头像的路径映射到这四个编号，
  现有素材零迁移成本。
- `#004+` 自由扩展，多少组都行（以后表情搭配更多就靠这里）。
- face 与 chara 是两套独立编号、两个文件夹（face/ 与 chara/），
  节名即文件夹名。

## 对话条目按编号指定头像

- 对白格式扩展：`{text="...", face=5, chara=2}`（数字即 #005 / #002）；
  未指定时回落语义位（说话场景 → 000/001/002/003 旧规则）。
- `ui/pilots` 的对白渲染与立绘框按编号解析 face.tbl。

## 角色配置覆盖（角色 lua 覆盖系统）

- 角色目录 `override.lua`（表值），加载时 deep-merge 到该角色的
  机体配置之上：必杀技类型/参数、武器数值、[behavior] 都可按角色覆盖。
  同机型不同角色由此有差异（某人的狙击必杀更强、某人的换位更激进）。
- 优先级：override.lua > 机型 tbl > 系统默认；冲突以最深路径为准。

## 左右面板对白独立子目录

- `teams/<队>/advisor/dialogue.lua` 拆为
  `advisor/left/dialogue.lua`、`advisor/right/dialogue.lua`、
  `advisor/commander/dialogue.lua`（+ 战前小剧场 `intro.lua`）。
- 面板文本不再与角色判定对白混在一个文件，避免越写越臃肿
  （用户明确要求"不要写在角色里"）。
