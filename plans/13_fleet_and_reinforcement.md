# 计划 13：编队与增援——上阵 7 人、阵营增援、自定义编队存档

来源：用户反馈 2026-09-11（"最多上阵 7 人，其他同阵营角色由增援召唤，
不召唤随机池；随机池以后删掉；自定义编队+存档记住上次编队；
弹丸论破 16 人不能都上场要有选择"）。

## 设计

- **上阵上限**：出击编队最多 7 名作战成员（config 常量 `deploy_limit = 7`，
  可调）。母舰/指挥官是否占名额：默认**不占**（指挥官+7 队员），
  配置可切换。
- **阵营增援**：增援只从**本阵营未上场**的角色中召唤（死了的可以再召唤，
  上限仍受部队总数约束）。增援菜单从"随机抽"改为"选人"：
  列出阵营内未在场角色供挑选，价格沿用现有档位。
- **随机池退役**：`teams/default`（混池）与 `systems/random_roster.lua`
  标记 deprecated——本计划先让选人界面不再默认它，验证一个版本后删除。
- **自定义编队**：
  - 部署界面重做：两栏（阵营成员列表 / 上阵名单），点选成员 + 机型分配，
    超过 7 人禁止再选并提示；其余成员自动成为增援池。
  - 存档：`saves/loadout.tbl` 按 `team_id` 记录上次编队（成员、机型、
    增援池顺序），下次进入部署界面默认载入。
- 16 人阵营（如弹丸论破）由此成立：选 7 上场，其余 9 人全部可增援。

## 步骤

1. `systems/simulation.deploy` 重构：deploy(team_id, loadout) 接受显式名单；
   UI 部署界面（两栏选人 + 机型 + 载入/保存上次编队）。
2. `systems/economy` 增援项改造：随机增援 → 选人增援（复用两栏列表的
   简化版）；`random_roster` 断开引用。
3. `systems/preferences` 或独立 `saves/loadout.tbl` 读写上次编队。
4. `teams/default` 标记 deprecated 并从选择列表隐藏。

## 验收

- [ ] 16 人阵营：只能上阵 7 人（含提示），其余角色增援可召唤，
      战场不出现重复角色，不出现非本阵营角色。
- [ ] 重启游戏后部署界面默认恢复上次编队。
- [ ] 全量 verify 绿；`random_roster` 无运行时引用（删除前状态）。

## 完成后

删除本文件（随机池本体的删除并入计划 08 的清理清单执行）。
